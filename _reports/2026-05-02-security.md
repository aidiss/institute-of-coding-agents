# Security Brief — 2026-05-02

Track of vulnerabilities, supply chain attacks, and safety incidents affecting AI coding agents.

---

## Incidents & Vulnerabilities

### Codex, Claude Code, and Copilot Credential Breaches — April 2026 Wave
**Status: Disclosed / Ongoing**

VentureBeat and Softtechhub reported a nine-month wave of attacks culminating in April 2026 in which all three major AI coding agents — OpenAI Codex, Anthropic Claude Code, and GitHub Copilot — confirmed credential compromises. IBM X-Force analysis of six confirmed exploitation paths found a consistent pattern: attackers targeted IAM credentials and API keys held in the agent's runtime environment, not the underlying models. In every case the attacker used a stolen credential to authenticate directly to a production system rather than trying to subvert the AI itself.

- **Affected:** Codex, Claude Code, Copilot (all versions at time of incident)
- **Attack vector:** Prompt injection → credential exfiltration → production system access
- **Fix:** No single patch; mitigations are operational (least-privilege IAM, short-lived tokens, runtime sandboxing)

### RoguePilot — GitHub Copilot Passive Prompt Injection via Issues (GITHUB_TOKEN Theft)
**Status: Disclosed / GitHub acknowledged**

Orca Security published the RoguePilot advisory demonstrating a passive prompt injection attack against GitHub Copilot's agentic review and issue-triage mode. An attacker embeds a hidden HTML comment in a GitHub Issue. When Copilot's agent processes the issue, it exfiltrates the `GITHUB_TOKEN` to an attacker-controlled endpoint and triggers a Codespaces workflow that hands over full repository write access. No contributor-level access is required to post the malicious issue — any public repository is a valid target.

- **Affected:** GitHub Copilot agentic mode (issue triage / PR review); public and private repositories
- **Data at risk:** `GITHUB_TOKEN` → repository write access, secrets stored in Actions
- **Fix:** GitHub acknowledged the report; patch status unconfirmed. Mitigation: restrict Copilot token scopes to read-only where possible; pin `permissions: read-all` in workflows.

### CVE-2026-21516 — GitHub Copilot for JetBrains Command Injection (CVSS 8.8)
**Status: Patched — update to version 1.5.63**

A command injection vulnerability in GitHub Copilot for JetBrains allows a malicious repository to inject OS commands through Copilot's inline completion context. An attacker crafts a source file whose surrounding code triggers command expansion when Copilot processes the completion request. Microsoft patched the issue on February 10, 2026 in version 1.5.63.

- **Affected:** GitHub Copilot for JetBrains versions 1.0.0 – 1.5.62
- **CVSS:** 8.8 High
- **Fix:** Upgrade to version 1.5.63 or later

### IDEsaster — 30+ CVEs Across AI IDE Ecosystem
**Status: Disclosed / Selectively patched**

A coordinated disclosure campaign catalogued over 30 vulnerabilities across Cursor, GitHub Copilot, Windsurf, Zed, and other major AI-integrated development environments. 24 CVEs have been formally assigned. The vulnerability classes include:

- **CurXecute (Cursor):** Arbitrary command execution via crafted `.cursorrules` files; fixed in Cursor 1.3.9.
- **MCPoison (Cursor):** Tool-poisoning attack in which a malicious MCP server instructs Cursor's agent to execute OS commands; fixed in Cursor 1.3.9.
- **Reprompt/repriming attacks (Copilot):** Injected context in completions causes Copilot to re-issue prompts that leak prior conversation context.

Several vendors have not yet issued patches. The full CVE list is tracked at [vulnerablemcp.info](https://vulnerablemcp.info/).

- **Affected:** Cursor (pre-1.3.9), GitHub Copilot, Windsurf, Zed, and others
- **Fix:** Cursor — update to 1.3.9+; other vendors — check individual advisories

### CVE-2026-25723 — Claude Code File-Write Restriction Bypass via Piped Commands
**Status: Patched — update to version 2.0.55 or later**

A researcher identified that Claude Code's file-write restrictions did not validate commands piped through `sed` and `echo`, allowing agent-mode workflows to escape the project sandbox and write to arbitrary paths on the host filesystem. Anthropic patched the issue in version 2.0.55; the full patch set covering this and two related sandbox escapes is in version 2.1.90.

- **Affected:** Claude Code versions prior to 2.0.55
- **Fix:** Upgrade to 2.1.90 or later (covers all three related CVEs)

### Google Antigravity — Critical RCE via Prompt Injection (Patched)
**Status: Disclosed / Patched**

Google patched a critical RCE flaw in Antigravity, its AI-based agentic IDE environment. Researchers produced a proof-of-concept prompt injection that escaped Antigravity's execution sandbox and achieved arbitrary code execution on the host. Google confirmed the patch is deployed; no CVE number has been published.

- **Affected:** Google Antigravity (versions prior to patch date)
- **Fix:** Patch deployed by Google; no user action required for cloud-hosted instances

## Supply Chain

### MCP STDIO Cascade — Protocol Flaw Continues Generating CVEs
**Status: Protocol flaw unpatched / Individual projects remediating**
**CVEs: CVE-2025-49596, CVE-2026-22252, CVE-2026-22688, CVE-2025-54994, CVE-2025-54136, and growing**

The systemic design flaw in Anthropic's MCP STDIO interface — which executes a configured OS command before returning any error, allowing arbitrary command injection — remains unaddressed in the reference SDK across Python, TypeScript, Java, and Rust. Anthropic has declined architectural changes to the core protocol. The cascading CVE list now spans 10+ downstream projects affecting 7,000+ public servers and 150M+ downloads. New CVEs from LibreChat, WeKnora, and Cursor this week confirm the flaw is being actively catalogued across the ecosystem.

Current best-practice mitigations (OX Security coordinated advisory):
- Block public IP access to MCP servers
- Run MCP services in sandboxed environments
- Treat all external MCP configuration as untrusted input
- Install only MCP servers from verified, audited sources
- Monitor and log all tool invocations

### Slopsquatting — Scale Grows as Agents Install Dependencies Autonomously
**Status: Ongoing / No ecosystem-level fix**

The slopsquatting attack surface — registering package names that AI coding tools repeatedly hallucinate — continues to expand as agentic workflows in Cursor, Claude Code, and Copilot Workspace increasingly install dependencies without human review. A 2026 security report by Sherlock Forensics found critical vulnerabilities in 92% of AI-generated code samples audited, with dependency confusion accounting for a significant fraction. Open-source LLMs hallucinate non-existent package names at ~21.7%, commercial models at ~5.2%; 58% of hallucinated names are repeated consistently across multiple runs, making them reliable targets. No PyPI or npm ecosystem-level detection has been deployed.

### Secrets Sprawl — AI-Service Credential Leaks Up 81% YoY
**Status: Ongoing**

GitGuardian's State of Secrets Sprawl 2026 report confirmed 28.65M new hardcoded secrets in public GitHub commits in 2025 (34% YoY increase). AI-service credentials — OpenAI keys, Anthropic keys, Hugging Face tokens — surged 81% YoY, driven by AI coding tools generating and committing API key literals in configuration files. The report directly links the trend to prompt injection and supply chain attacks (notably the LiteLLM supply chain attack of March 24, 2026) that convert locally exposed secrets into organizational risk.

## Research & Advisories

### Anatomy of a Vibe Coding Breach — Part 3 (Simon Roses Femerling)
Security researcher Simon Roses Femerling published Part 3 of his "Anatomy of a Vibe Coding Breach" series, a post-incident analysis of 2026's worst agentic AI security failures. The report documents the failure modes shared across the largest incidents: excessive agent permissions, missing human-in-the-loop approval steps for destructive operations, and reliance on vendor-supplied system prompts as the sole security boundary. The recurring lesson across incidents is that agent sandboxes provide much weaker isolation than traditional process sandboxes and should not be treated as security boundaries.

Reference: [simonroses.com](https://simonroses.com/2026/04/anatomy-of-a-vibe-coding-breach-lessons-from-2026s-worst-incidents-part-3/)

### OWASP — Prompt Injection in 73% of Production AI Deployments
OWASP's most recent assessment of production AI deployments found prompt injection present in 73% of evaluated systems, confirming it as the dominant vulnerability class in deployed AI agents. OWASP ranks it #1 in the LLM Top 10 list, and the rate has increased from 60% in 2025 assessments as AI agent adoption has accelerated. The assessment notes that most organizations still treat prompt injection as a theoretical risk rather than an active threat model.

Reference: [owasp.org/www-project-top-10-for-large-language-model-applications](https://owasp.org/www-project-top-10-for-large-language-model-applications/)

### ChatGPT Data Exfiltration via Hidden Outbound Channel — Patched
Check Point Research documented a covert exfiltration channel in ChatGPT's isolated code-execution runtime that allowed a malicious prompt to leak user messages, uploaded files, and session content to an external endpoint. OpenAI confirmed it had identified the issue internally and deployed a full fix on February 20, 2026. No CVE assigned.

Reference: [research.checkpoint.com](https://research.checkpoint.com/2026/chatgpt-data-leakage-via-a-hidden-outbound-channel-in-the-code-execution-runtime/)
