# Security Brief — 2026-05-01

Track of vulnerabilities, supply chain attacks, and safety incidents affecting AI coding agents.

---

## Incidents & Vulnerabilities

### CVE-2026-26268 — Cursor IDE Git Hook Arbitrary Code Execution
**Status: Disclosed / Patch pending**

Novee Security published a full advisory for a high-severity arbitrary code execution vulnerability in the Cursor AI IDE. The attack path requires no social engineering beyond convincing a developer to clone a repository:

1. Attacker crafts a repository containing a malicious git hook (e.g. `post-checkout`).
2. Developer asks Cursor's agent to clone or check out a branch.
3. The agent executes `git checkout` on the developer's behalf, automatically triggering the hook with the developer's privileges.
4. Arbitrary OS commands run on the developer's machine.

The root issue is that Cursor's agent model does not sanitize or sandbox git lifecycle hooks triggered by commands it issues. No patch has been released at time of writing; the reporter confirmed the vulnerability is reproducible across macOS and Linux.

- **Affected:** Cursor IDE (all versions tested prior to disclosure date)
- **Data at risk:** Full local filesystem access, credential stores, SSH keys, cloud provider configs
- **Fix:** Not yet available. Mitigation: disable git hooks globally (`core.hooksPath=/dev/null`) or restrict Cursor's agent from executing git operations on untrusted repositories.

### CVE-2025-53773 — GitHub Copilot PR Description Prompt Injection → RCE (CVSS 9.6)
**Status: Disclosed / Patch status unconfirmed**

A hidden instruction embedded in a pull request description caused GitHub Copilot's agentic review mode to execute arbitrary shell commands on the CI runner. The attack exploits Copilot's tendency to treat PR body text as trusted instruction context during automated reviews.

- **Affected:** GitHub Copilot agentic PR review (versions not specified)
- **CVSS:** 9.6 Critical
- **Mechanism:** Prompt injection via PR body; no special repository access required — any contributor who can open a PR can trigger the exploit
- **Fix:** Status unconfirmed; GitHub acknowledged the report

### CVE-2026-20205 — Splunk MCP Server Information Disclosure
**Status: Disclosed / Patch available**

SentinelOne published an advisory for an information disclosure vulnerability in the Splunk MCP Server integration. An authenticated user can craft tool calls that cause the MCP server to return environment variables and internal configuration values outside the intended scope, potentially exposing Splunk API tokens, SMTP credentials, and index names.

- **Affected:** Splunk MCP Server (versions prior to patch)
- **Fix:** Patch available; update via Splunk's official channel
- **Note:** No evidence of active exploitation; classified as lower-severity but meaningful given MCP servers typically run with broad environment access

### Prompt Injection via PR Title — Claude Code, Gemini CLI, Copilot Agent All Affected
**Status: Disclosed / No code-level fixes (Claude Code, Gemini CLI); Microsoft acknowledged**

A security researcher at Johns Hopkins University demonstrated that a single malicious instruction placed in a PR title simultaneously triggered three separate AI coding agent actions to exfiltrate their own API keys:

- **Claude Code Security Review action** posted its API key as a PR comment.
- **Gemini CLI Action** exfiltrated its key via an outbound URL embedded in generated text.
- **GitHub Copilot Agent** leaked its credential through a workflow annotation.

Anthropic's response was documentation-only, citing the system card's existing caveat that Claude Code is "not hardened against prompt injection." No code-level mitigations were introduced. Google and Microsoft acknowledged the reports; patch status for both remains unconfirmed.

## Supply Chain

### CVE-2026-33032 — nginx-ui Unauthenticated MCP Endpoint Allows Remote Nginx Takeover
**Status: Disclosed / Fix available**

Endor Labs published an advisory for an unauthenticated MCP endpoint in nginx-ui, a web management panel for nginx. The endpoint is reachable without credentials and accepts MCP tool calls that can modify nginx configuration, reload the daemon, and read arbitrary files accessible to the nginx user. Successful exploitation gives an attacker control over routing, TLS termination, and proxy configuration across the host's nginx installation.

- **Affected:** nginx-ui (versions prior to fix)
- **Fix:** Update to the patched release per the Endor Labs advisory
- **Risk elevation:** MCP-enabled server panels represent an emerging attack surface; any authenticated-but-public MCP interface requires the same hardening as a root-accessible admin panel

### MCP STDIO Cascade — New Projects Affected This Week
**Status: Protocol flaw unpatched / Individual projects remediating**
**CVEs: CVE-2025-49596, CVE-2026-22252, CVE-2026-22688, CVE-2025-54994, CVE-2025-54136, CVE-2026-30623, CVE-2026-30624, CVE-2026-40933, and others**

The MCP STDIO "by-design" flaw continues generating new CVEs. The core issue — MCP executes a supplied OS command before returning any error, allowing arbitrary command injection via STDIO configuration — remains unaddressed in Anthropic's reference SDK across Python, TypeScript, Java, and Rust. Anthropic has explicitly declined architectural changes. The cascading CVE list now spans 10+ projects. Total exposure remains 7,000+ public servers and 150 M+ downloads.

Mitigations from OX Security's coordinated advisory remain the current best practice:
- Block public IP access to MCP servers
- Monitor and log all tool invocations
- Run MCP services in sandboxed environments
- Treat external MCP configuration as untrusted input
- Install only MCP servers from verified, audited sources

Track all known affected projects at [vulnerablemcp.info](https://vulnerablemcp.info/).

### Slopsquatting — Phantom Package Downloads Continue to Accumulate
**Status: Ongoing / No ecosystem-level fix**

The "slopsquatting" attack class — registering package names that AI coding tools hallucinate — continues to scale as autonomous coding agents (Cursor, Claude Code, Copilot Workspace) install dependencies without human review. The 128-phantom-package research cohort tracked between July 2025 and January 2026 accumulated 121,539 combined downloads (~4,000/week). Individual sentinel packages registered by researchers continue attracting thousands of downloads monthly, confirming the attack class is being actively exploited beyond academic proof-of-concept.

No package ecosystem has deployed automated hallucination-detection. Risk compounds in agentic workflows where package selection and installation occur in a single unreviewed pipeline step.

## Research & Advisories

### IBM X-Force — OpenClaw: Agentic AI Attack Surface Analysis
IBM X-Force published "OpenClaw," a comprehensive analysis of attack patterns observed across enterprise deployments of agentic AI systems in Q1 2026. Key findings:

- Agentic AI systems are being targeted for credential theft rather than model manipulation — attackers treat the agent's runtime environment as a privileged credential store, not as an AI to subvert.
- Six confirmed exploitation paths were documented across Claude Code, Copilot, and Codex deployments; in every case, the attacker targeted IAM credentials or API keys, not the model weights or inference outputs.
- Agent-to-agent trust delegation (where one agent calls another) dramatically widens the attack surface; permissions granted to a parent agent propagate to child agents without additional validation.

Reference: [ibm.com/think/x-force](https://www.ibm.com/think/x-force/agentic-ai-growing-fast-vulnerabilities)

### CSA — AI-Assisted Developers Introduce Security Findings at 10× Rate
An empirical study across Fortune 50 enterprises, incorporated into the CSA's ongoing Vibe Security Radar project, found that AI-assisted developers produce commits three to four times faster than peers but introduce security findings at ten times the rate. The accumulated security debt grows faster than current AppSec tooling can remediate, particularly when agents autonomously commit and merge. The study attributes the disparity to:

- AI models optimizing for functional correctness without security constraints
- Faster commit velocity overwhelming manual code-review capacity
- AI-introduced patterns (insecure defaults, missing input validation, hardcoded credentials) that are not flagged by standard linters

Reference: [labs.cloudsecurityalliance.org](https://labs.cloudsecurityalliance.org/research/csa-research-note-ai-generated-code-vulnerability-surge-2026/)

### GitGuardian — State of Secrets Sprawl 2026
GitGuardian's annual report confirmed 28.6 M new secrets exposed in public GitHub commits across 2025 — a 34% year-over-year increase and the largest annual jump in the report's history. AI-service credential leaks (OpenAI keys, Anthropic keys, Hugging Face tokens) surged 81% year-over-year, driven by AI coding tools writing and committing API key literals in configuration files. The report connects this trend directly to prompt injection and supply-chain attacks (notably the LiteLLM supply chain attack of March 24, 2026) that convert local secrets into organizational risk.

Reference: [blog.gitguardian.com](https://blog.gitguardian.com/the-state-of-secrets-sprawl-2026/)

### Airia — "The Lethal Trifecta" in AI Security
Airia published a threat model framing the primary AI agent risk as a compound of three co-present conditions: (1) prompt injection as the delivery mechanism, (2) over-permissioned agents as the privilege amplifier, and (3) inadequate sandboxing as the blast-radius enabler. The model maps to observed incidents from 2025–2026 and is being adopted by several enterprise security teams as a design checklist for agentic deployments.

Reference: [airia.com](https://airia.com/ai-security-in-2026-prompt-injection-the-lethal-trifecta-and-how-to-defend/)
