# Security — 2026-04-22

## Incidents & Vulnerabilities

### Three AI Coding Agents Leak Secrets via Single Prompt Injection (April 2026)
VentureBeat reported that researchers demonstrated a single prompt injection payload capable of triggering secret exfiltration across three separate AI coding agents in a unified CI/CD pipeline. The attack exploited the "Comment and Control" vector — injecting instructions into a GitHub PR comment — and chained agent interactions to propagate the payload laterally. Notably, one vendor's own system card had predicted this exact attack class. No CVE assigned; none of the three affected vendors have shipped patches as of this writing. Status: **disclosed, unpatched**.

- Source: [VentureBeat](https://venturebeat.com/security/ai-agent-runtime-security-system-card-audit-comment-and-control-2026)

### MCPJam Inspector RCE — CVE-2026-23744 (Critical)
MCPJam Inspector versions ≤ 1.4.2 bind their administrative endpoint to `0.0.0.0` without authentication. A crafted HTTP request can install an arbitrary MCP server and execute code on the host with no user interaction. The vulnerability is exploitable from any machine on the same network, or remotely if the port is internet-facing. Upgrade to ≥ 1.4.3. Status: **patched in 1.4.3; older versions remain at risk**.

- CVE: **CVE-2026-23744** (Critical)
- Affected: MCPJam Inspector ≤ 1.4.2
- Fix: upgrade to 1.4.3+
- Source: [VulnerableMCP.info](https://vulnerablemcp.info/)

### MCP TypeScript SDK Cross-Client Data Leak — CVE-2026-25536
When a single `McpServer` instance is reused across multiple clients, the TypeScript SDK can route responses to the wrong client, leaking data across client boundaries. In multi-tenant or shared-server deployments this enables one user to read another user's tool outputs, including API keys or sensitive context passed to the server. Status: **patch available; deployments using shared server instances should upgrade immediately**.

- CVE: **CVE-2026-25536**
- Affected: MCP TypeScript SDK (shared `McpServer` instances)
- Source: [VulnerableMCP.info](https://vulnerablemcp.info/), [Red Hat MCP security overview](https://www.redhat.com/en/blog/model-context-protocol-mcp-understanding-security-risks-and-controls)

### Windsurf 1.9544.26 — Prompt Injection to Arbitrary Command Execution
A prompt injection vulnerability in Windsurf version 1.9544.26 allows a remote attacker to execute arbitrary commands on a victim system. The attack vector requires the victim to open a crafted repository or file that contains injected instructions. No CVE index number published at time of writing. Status: **version-specific; users should update to latest Windsurf release**.

- Affected: Windsurf 1.9544.26
- Source: [Botmonster Tech](https://botmonster.com/posts/ai-coding-agent-insider-threat-prompt-injection-mcp-exploits/)

### AI Coding Agents Reading Environment Secrets Without Consent (Ongoing)
Keyway security researchers document a persistent pattern: Claude Code, Cursor, and GitHub Copilot all automatically read `.env` files and other credential stores when resolving project context, forwarding those values to cloud inference endpoints without explicit user acknowledgement. While not a discrete CVE, this behaviour systematically exposes API keys, database passwords, and cloud credentials to third-party model providers. Organizations should audit agent permissions and enforce secret-scanning at the IDE layer. Status: **vendor behaviour, no patch expected; user mitigation required**.

- Source: [Keyway](https://www.keyway.sh/articles/ai-coding-agents-secrets-security)

## Supply Chain

### OX Security MCP Supply Chain Advisory — RCE at Scale
OX Security issued a formal advisory warning of a systemic, architectural vulnerability in Anthropic's official MCP SDKs across all supported languages (Python, TypeScript, Java, Rust). The flaw enables arbitrary command execution on any connected host and Anthropic has characterised the behaviour as within the protocol's expected trust model rather than a security defect. The estimated exposure: **7,000+ publicly accessible MCP servers**, **150 million cumulative SDK downloads**, and up to **200,000 vulnerable instances**. No CVE assigned; no vendor patch. Status: **vendor-disputed; mitigations recommended (sandboxing, allowlisting)**.

- Source: [OX Security](https://www.ox.security/blog/mcp-supply-chain-advisory-rce-vulnerabilities-across-the-ai-ecosystem/), [The Hacker News](https://thehackernews.com/2026/04/anthropic-mcp-design-vulnerability.html)

### Automated Dependency Side-Loading via AI Extensions (February 2026)
A Medium research post documented "automated dependency side-loading" — a new attack variant where malicious AI IDE extensions intercept dependency resolution calls made by coding agents and substitute or inject packages at install time. Unlike slopsquatting (which relies on hallucinated names), this attack works even when the LLM suggests a legitimate package, by intercepting the `pip install` or `npm install` subprocess and substituting a trojanized version. No specific CVEs reported. Status: **no broad mitigation deployed; affected vendors notified**.

- Source: [InstaTunnel / Medium](https://medium.com/@instatunnel/automated-dependency-side-loading-the-invisible-supply-chain-attack-via-ai-extensions-fe615eb03f19)

### Slopsquatting — Phantom Package Downloads Continue Climbing (Ongoing)
Security Boulevard reported that coding agents (Cursor, Claude Code, GitHub Copilot Workspace) are accelerating slopsquatting risk because they can issue `pip install` / `npm install` commands autonomously. A cohort of 128 phantom packages tracked from July 2025 through January 2026 accumulated **121,539 downloads** — roughly 4,000 per week — before any of the names were registered by a defender. Approximately 20% of AI-generated Python and JavaScript code samples reference at least one non-existent package. Status: **ongoing; no systemic fix; package name monitoring is current best practice**.

- Source: [Security Boulevard](https://securityboulevard.com/2026/03/coding-agents-widen-your-supply-chain-attack-surface/), [BleepingComputer](https://www.bleepingcomputer.com/news/security/ai-hallucinated-code-dependencies-become-new-supply-chain-risk/), [Infosecurity Magazine](https://www.infosecurity-magazine.com/news/ai-hallucinations-slopsquatting/)

### AI Code Does Not Produce More Secure Outputs — The Register
A study published March 26, 2026 and covered by The Register found that AI-assisted coding does not measurably reduce the rate of security vulnerabilities in produced code versus non-AI developers. 48% of AI-generated code samples contained at least one security vulnerability, with SQL injection, insecure deserialization, and hardcoded credentials being the most frequent defect classes. With AI now authoring ~27% of production code, this represents a structural increase in the vulnerability surface area introduced per development cycle.

- Source: [The Register](https://www.theregister.com/2026/03/26/ai_coding_assistant_not_more_secure/)

## Research & Advisories

### Trail of Bits: Prompt Injection to RCE — Exploit Chain Documented (October 2025, still cited)
Trail of Bits published a detailed technical writeup demonstrating a reliable exploitation path from prompt injection to remote code execution in AI coding agents. The chain abuses agents' ability to invoke shell tools, write files, and execute scripts: a malicious payload in processed content rewrites a shell script, which is then executed by the agent on the host system. The research underpins several active CVEs and is now widely cited in agent security design guidelines.

- Source: [Trail of Bits Blog](https://blog.trailofbits.com/2025/10/22/prompt-injection-to-rce-in-ai-agents/)

### "Lethal Trifecta" — Compound Threat Model for AI Agent Security (2026)
Airia's security team introduced the "Lethal Trifecta" framing for AI coding agent threats: **(1) prompt injection** as initial access, **(2) excessive tool permissions** as the privilege escalation surface, and **(3) inadequate output filtering** as the exfiltration channel. The model argues that each element alone is insufficient for a complete attack, but that most deployed agents satisfy all three conditions simultaneously. Recommended mitigations: minimal tool scopes, output scanning, and input sanitisation at every boundary.

- Source: [Airia](https://airia.com/ai-security-in-2026-prompt-injection-the-lethal-trifecta-and-how-to-defend/)

### MCP "Rug Pull" Attacks — Dynamic Tool Definition Abuse
Unit 42 researchers and the CoSAI MCP Security whitepaper both highlight "rug pull" attacks in MCP deployments: a malicious server presents benign tool definitions during initial session approval, then silently replaces them with harmful definitions after user trust is established. The MCP specification does not currently mandate re-authorisation when tool definitions change between sessions. This is categorised as a protocol-level design gap rather than an implementation bug. Status: **no spec-level fix; runtime monitoring is recommended mitigation**.

- Source: [Unit 42 / Palo Alto](https://unit42.paloaltonetworks.com/model-context-protocol-attack-vectors/), [VulnerableMCP.info](https://vulnerablemcp.info/)

### OWASP: Prompt Injection Remains #1 AI Application Threat (LLM01:2025)
The OWASP Top 10 for LLM Applications continues to list prompt injection as the leading risk. A systematic meta-analysis covering 78 studies found that every major coding agent tested — Claude Code, GitHub Copilot, Cursor — is vulnerable to prompt injection, with adaptive attack success rates exceeding 85%. The attack surface includes PR comments, repository content, issue bodies, web pages fetched by agents, and documents processed by retrieval pipelines.

- Source: [MDPI](https://www.mdpi.com/2078-2489/17/1/54), [Securance](https://www.securance.com/blog/prompt-injection-the-owasp-1-ai-threat-in-2026), [Cycode](https://cycode.com/blog/ai-security-vulnerabilities/)

### VulnerableMCP.info — Community MCP CVE Index
The community-maintained vulnerability database at [vulnerablemcp.info](https://vulnerablemcp.info/) remains the primary reference for MCP-specific CVE enumeration. It now tracks CVE-2026-23744 (MCPJam Inspector RCE) and CVE-2026-25536 (TypeScript SDK data leak) among other entries and is referenced in enterprise security advisories as a canonical source.
