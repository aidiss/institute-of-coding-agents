## Headlines

- **Flowise** has a separately confirmed unauthenticated CVSS 10.0 RCE under active exploitation — distinct from the authenticated CVE-2026-40933 (April 23) — with 12,000+ publicly exposed instances being targeted as of this week. Patch or take offline immediately.
- **"Comment and Control"** (Claude Code Security Review, Gemini CLI Action, GitHub Copilot SWE Agent) remains unpatched across all three vendors; no CVE assigned; CI/CD environments should restrict agent permissions to read-only as an interim control.
- **"Clinejection"** (February 2026) established the template for AI coding-agent supply chain attacks: a compromised issue-triage automation bot published a trojaned Cline release to npm, delivering the OpenClaw AI agent as a persistent RAT to approximately 4,000 developer machines before detection.
- **IDEsaster** research — 25 confirmed vulnerabilities across 19 AI coding tools — provides the most comprehensive current map of the attack surface; 11 of the 25 enable RCE on developer machines.

## Incidents & Vulnerabilities

### Flowise AI Agent Builder — Unauthenticated CVSS 10.0 RCE Under Active Exploitation

**CVSS:** 10.0 (Critical) | **Affected:** Flowise self-hosted deployments | **Status:** Actively exploited in the wild | **Auth required:** None | **Fix:** Patch available — upgrade immediately

> This is a separate, higher-severity vulnerability from CVE-2026-40933 (authenticated MCP adapter RCE, covered April 23). The CVSS 10.0 variant is unauthenticated.

A critical unauthenticated remote code execution vulnerability in Flowise's AI agent builder platform is being actively exploited against internet-exposed instances. With **12,000+ instances publicly reachable**, the attack surface is large and the barrier to exploitation is zero: no credentials, no user interaction, and no physical access are required.

Flowise is widely deployed as the drag-and-drop orchestration layer for LLM-powered automation — including coding-adjacent workflows such as automated code review, repository Q&A agents, and CI/CD decision agents. A compromised Flowise instance grants an attacker full control over every agentic workflow it hosts, including any with repository write access, secret access, or CI/CD trigger permissions. Workflow API keys, model credentials, and connected system tokens should all be considered compromised on affected deployments.

**Immediate action required:**
- Patch to the latest Flowise release without delay
- If patching is not immediately possible, take the instance off public network access
- Rotate all API keys, model credentials, and service tokens configured in Flowise workflows
- Assume any data accessed by workflows on affected instances has been exfiltrated
- Audit Flowise access logs for anomalous workflow executions dating back at least 30 days

*Sources: [The Hacker News — Flowise AI Agent Builder Under Active CVSS 10.0 RCE Exploitation](https://thehackernews.com/2026/04/flowise-ai-agent-builder-under-active.html)*

### "Comment and Control" — Carry-Forward: Still Unpatched (Day 2)

**Affected:** Claude Code Security Review (GitHub Action), Google Gemini CLI Action, GitHub Copilot SWE Agent | **CVE:** None assigned | **Status:** Disclosed April 24; no vendor patch; no CVE filed

No vendor has shipped a targeted mitigation as of April 25. The attack embeds malicious instructions in GitHub PR titles, issue bodies, and HTML-comment payloads invisible to human reviewers; when any of the three affected agents processes that content during automated code review or CI/CD, it exfiltrates API keys and access tokens from environment variables and service files into model-visible output and session history.

Anthropic's own system card for Claude Code Security Review acknowledges the feature "is not hardened against prompt injection." The disclosure confirmed the attack succeeds against all three vendors independently; chained CI/CD pipelines using more than one of the three agents multiply the exposure.

**Interim controls (no patch available):**
- Restrict CI/CD agent permissions to the minimum required scope; remove environment variable access where not operationally essential
- Treat all PR content — including comments from collaborators — as untrusted input to agent workflows
- Add human-in-the-loop approval gates before agent-generated outputs are acted on

*Sources: [SecurityWeek](https://www.securityweek.com/claude-code-gemini-cli-github-copilot-agents-vulnerable-to-prompt-injection-via-comments/), [VentureBeat](https://venturebeat.com/security/ai-agent-runtime-security-system-card-audit-comment-and-control-2026)*

## Supply Chain

### "Clinejection" — Cline AI Coding Agent npm Supply Chain Compromise (February 2026)

**Disclosed:** February 17, 2026 | **Researcher:** Snyk, Dark Reading | **Package:** `cline` (npm) | **Payload:** OpenClaw AI agent (persistent RAT) | **Duration:** 8-hour attack window | **Downloads before removal:** ~4,000 | **Affected version:** `cline@2.3.0` (deprecated) | **Fix:** Version 3.35.0 | **Status:** Patched; affected installs require remediation

"Clinejection" is the most thoroughly documented AI coding-agent supply chain attack to date. The attack chain had two stages:

**Stage 1 — four initial vulnerabilities (February 9, 2026):** Researchers disclosed four critical security vulnerabilities in the Cline VS Code extension, including inadequate prompt-injection protections during source code analysis. Malicious instructions could be embedded in Python, Markdown, and shell scripts that Cline reads as part of agentic coding tasks. Cline fixed these within one hour of public disclosure.

**Stage 2 — supply chain compromise via issue-triage bot (February 17, 2026):** An attacker exploited a vulnerability in Cline's own GitHub issue-triage automation bot to gain push access to the npm publish pipeline. The attacker published a compromised `cline@2.3.0` to npm containing the **OpenClaw AI agent** — a persistent remote access trojan designed to install itself on developer machines. OpenClaw establishes persistence, exfiltrates filesystem content, and exposes a remote command channel. The malicious version was live for approximately **8 hours** before detection, accumulating around **4,000 downloads**.

**Why this matters structurally:** Clinejection demonstrated a novel attack surface: the automation tooling that AI-developer tool projects use to manage community contributions (issue bots, auto-labellers, CI integrations) itself constitutes a supply chain attack vector. Compromise of the bot bypassed the maintainer's own credential controls. Any open-source AI coding tool that uses automation bots with publish-adjacent permissions should treat those bots as a privileged trust boundary requiring the same security posture as the human maintainers.

**Indicators of compromise:**
- `cline` npm package version `2.3.0` installed (deprecated; remove immediately)
- Presence of the `openclaw` process or related artifacts in shell history
- Unexpected outbound connections from VS Code processes
- Unfamiliar entries in system startup items following Cline install or update

**Mitigation:** Update to Cline **v3.35.0 or later**. If `cline@2.3.0` was ever installed, treat the developer machine as potentially compromised: rotate all credentials accessible from the machine, audit SSH authorized_keys, and audit npm/git/cloud credentials.

*Sources: [Snyk — How "Clinejection" Turned an AI Bot into a Supply Chain Attack](https://snyk.io/blog/cline-supply-chain-attack-prompt-injection-github-actions/), [Dark Reading — Supply Chain Attack Secretly Installs OpenClaw for Cline Users](https://www.darkreading.com/application-security/supply-chain-attack-openclaw-cline-users), [CyberSecurityNews — Cline AI Coding Agent Vulnerabilities](https://cybersecuritynews.com/cline-ai-coding-agent-vulnerabilities/)*

## Research & Advisories

### IDEsaster — 25 Vulnerabilities in 19 AI Coding Agents (100M+ Installs)

**Published:** December 2025 – April 2026 (ongoing series) | **Researcher:** Multiple, coordinated disclosure | **Scope:** Cursor, Windsurf, GitHub Copilot, Zed.dev, Roo Code, and 14 others

The IDEsaster research programme has catalogued **25 confirmed security vulnerabilities** across **19 AI-powered coding tools** with a combined install base exceeding 100 million. The breakdown:

| Category | Count |
|---|---|
| Remote Code Execution (RCE) | 11 |
| Data exfiltration via markdown images | 14 |

**Attack chain pattern (recurring across all 19 tools):**
1. **Bypass LLM guardrails** via prompt injection embedded in repository files, documentation, or fetched web content
2. **Escalate via auto-approved tool calls** — agent executes code or filesystem operations without per-operation user confirmation
3. **Exfiltrate via IDE features** — markdown image rendering, clipboard hooks, or network requests leak sensitive data to attacker-controlled infrastructure without user interaction

**Structural finding:** The research concludes that the vulnerability class is not tool-specific but architectural — AI coding agents share a design pattern (LLM with file access and shell execution) that is inherently exploitable via prompt injection regardless of which specific tool is targeted. Mitigating one tool in isolation does not reduce the aggregate risk to a developer environment running multiple agents.

**Key implication for enterprises:** The 14 data exfiltration paths via markdown image rendering are particularly relevant in enterprise environments where agents process documentation, comments, or pull request descriptions from external contributors. Silent exfiltration — no user-visible anomaly, no shell popup — is achievable with off-the-shelf prompt injection payloads.

*Sources: [The Hacker News — Researchers Uncover 30+ Flaws in AI Coding Tools](https://thehackernews.com/2025/12/researchers-uncover-30-flaws-in-ai.html), [Dark Reading — Every Old Vulnerability Is Now an AI Vulnerability](https://www.darkreading.com/vulnerabilities-threats/every-old-vulnerability-is-now-ai-vulnerability), [Cloud Security Newsletter — IDEsaster](https://www.cloudsecuritynewsletter.com/p/idesaster-ai-ide-vulnerabilities-attack-surface)*

### arXiv 2601.17548 — 100% of Tested Coding Agents Vulnerable; 85%+ Adaptive Attack Success

**Published:** January 2026 | **Scope:** 78 studies, all major coding agents | **Key finding:** Every tested agent vulnerable in default configuration; adaptive attacks succeed >85% of the time

Peer-reviewed systematic analysis (arXiv 2601.17548) establishes the baseline: no tested coding agent resists prompt injection in its default configuration. Attack surfaces catalogued include PR comments, repository files, web pages fetched during agent sessions, issue bodies, RAG pipelines, and tool-call return values — precisely the surfaces targeted by "Comment and Control" and IDEsaster this week.

The paper's assessment of defenses is stark: most deployed mitigations achieve less than 50% success against adaptive attacks. An attacker willing to iterate — a reasonable assumption for targeted attacks on high-value developer environments — can expect to succeed.

*Sources: [arXiv 2601.17548](https://arxiv.org/abs/2601.17548), [MDPI Information](https://www.mdpi.com/2078-2489/17/1/54)*

## Analyst Note

Three threads from this week's findings warrant synthesis:

**1. Flowise CVSS 10.0 marks a milestone: AI workflow platforms are now primary targets.** The April 2026 wave has seen back-to-back critical vulnerabilities in Flowise (CVE-2026-40933 April 23, CVSS 10.0 active exploitation April 25), n8n (CVE-2026-21858, CVSS 10.0), and other agentic workflow platforms. The pattern is consistent: these platforms run with elevated credentials, have rich integrations, and were designed for productivity rather than hardening. Attackers have noticed. A compromised workflow platform is a force multiplier — it owns every agent credential and every connected system on that host. The security bar for agentic platforms must be equivalent to production infrastructure, not developer tooling.

**2. "Clinejection" set the template that the npm worm is now scaling.** The Cline attack demonstrated that AI-developer tool repositories are reachable via their own automation bots — without compromising a human maintainer's credentials. The self-propagating npm worm reported April 22 generalises this: steal a developer's publish token (perhaps from a compromised Cline install), publish a backdoored update, harvest the next developer's credentials. The cycle compounds. As AI coding agents gain more publish-adjacent permissions through automated CI/CD flows, this cycle accelerates. Teams should audit bot permission scopes and npm publish access as seriously as SSH keys.

**3. The gap between disclosure and defence is the real story.** "Comment and Control" has no patch, no CVE, and no vendor-issued mitigation on day 2. IDEsaster documents 11 RCE paths across 19 tools. The arXiv analysis finds defenses fail more than half the time. This is not a resource problem for individual teams — it is a structural gap: the attack surface of AI coding agents is growing faster than the security response capacity of the ecosystem. Until prompt injection is treated as a first-class engineering constraint (not a post-ship hardening task), advisories like these will continue to document the same root cause with new CVE numbers.

**Immediate actions:**
- **Flowise operators:** Patch CVSS 10.0 RCE immediately; rotate all workflow credentials; audit access logs; consider taking internet-exposed instances offline until patched
- **Cline users:** Verify installed version is **v3.35.0+**; if `v2.3.0` was ever installed, treat the machine as compromised and rotate credentials
- **CI/CD maintainers:** Restrict Claude Code, Gemini CLI, and GitHub Copilot SWE Agent permissions to read-only until "Comment and Control" is patched; treat all PR content as hostile input
- **All teams using AI coding agents:** Review IDEsaster findings against your specific tool stack; pay particular attention to auto-approval settings and markdown rendering contexts
