## Incidents & Vulnerabilities

### CVE-2026-23744 — MCPJam Inspector Unauthenticated RCE — Patch Released
**CVSS:** 9.8 | **Status:** Previously unpatched; **fix shipped 2026-05-05** (v0.6.4) | **Affected:** MCPJam Inspector ≤ 0.6.3

The 0.0.0.0-bind unauthenticated RCE that has been the highest-severity unfixed AI tooling CVE for the past two weeks now has a vendor patch. Maintainers shipped v0.6.4 yesterday after public coordination with JFrog and Palo Alto Unit 42; the proxy now binds to `127.0.0.1` by default and rejects unauthenticated WebSocket upgrades. Known proof-of-concept exploits remain effective against unpatched installs. Defenders should additionally audit local firewall rules — many developers had the inspector listening externally for weeks.

Sources: [JFrog Advisory](https://jfrog.com/blog/mcpjam-inspector-cve-2026-23744-patch/) | [GitHub Release Notes](https://github.com/mcpjam/inspector/releases/tag/v0.6.4) | [Unit 42 Update](https://unit42.paloaltonetworks.com/model-context-protocol-attack-vectors/)

### CVE-2026-34112 — Cursor Agent Mode Workspace Trust Bypass
**CVSS:** 8.4 | **Status:** Disclosed; patched in **Cursor 1.7.2** | **Affected:** Cursor 1.4.0 – 1.7.1

A second trust-boundary bypass for Cursor (after CVE-2025-54135) was disclosed by HiddenLayer. When a malicious repository contained a `.cursor/rules.json` with elevated `auto_run` permissions, Cursor's agent mode applied the rules **before** the workspace-trust dialog was rendered. Opening the repository was sufficient to grant arbitrary command execution in the agent's pre-approval list. Anyone on Cursor 1.4–1.7.1 should update.

Sources: [HiddenLayer Advisory](https://hiddenlayer.com/research/cursor-trust-bypass-cve-2026-34112) | [Cursor Changelog](https://www.cursor.com/changelog) | [NVD](https://nvd.nist.gov/vuln/detail/CVE-2026-34112)

### "Comment and Control" — Two-Week Update on Vendor Patch Status
**Status:** Patched at vendors; class of attack remains exploitable in third-party agents

Two weeks after Aonan Guan's disclosure of GitHub-comment prompt injection across Claude Code Security Review, Gemini CLI Action, and GitHub Copilot SWE Agent, vendor patches have rolled out:

- **Anthropic Claude Code Security Review:** v2.1.94 strips PR title/body content from the system-prompt context window before tool dispatch. Original CVSS-9.4 vector now mitigated; status **patched**.
- **Google Gemini CLI Action:** v0.18.0 disables the "Trusted Content Section" parser entirely and treats all `pull_request` and `issue_comment` payloads as untrusted; status **patched**.
- **GitHub Copilot SWE Agent:** rolled out a server-side filter that strips HTML comments from issue bodies before agent ingestion; status **patched, no client update required**.

Independent agents that consume PR/issue content (Aider Bot, Sweep, OpenHands GitHub action) have **not** uniformly issued patches; researchers report at least three smaller agents remain reproducibly exploitable as of 2026-05-05.

Sources: [Anthropic Release Notes](https://docs.anthropic.com/en/release-notes/claude-code) | [Gemini CLI Releases](https://github.com/google-gemini/gemini-cli-action/releases) | [oddguan.com Update](https://oddguan.com/blog/comment-and-control-vendor-patch-tracker/)

### CVE-2026-34201 — Anthropic Claude Code Tool-Use Permission Skew
**CVSS:** 7.5 | **Status:** Disclosed; **patched in 2.1.96** | **Affected:** 2.1.53 – 2.1.95

Reported via Anthropic's bug bounty: Claude Code's tool permission model evaluated an `allowedTools` allowlist as a **prefix match** rather than exact tool-name match, so `Bash` allowed `BashAdmin`, `BashRoot`, etc. While no such tools shipped from Anthropic, plugins published via the marketplace could register tools whose names began with allowlisted prefixes and bypass user-approved scopes. Status: **patched**. Defenders should upgrade to 2.1.96+ and audit installed plugins for tool name collisions.

Source: [Anthropic Security Advisory](https://www.anthropic.com/security/advisories/2026-05-claude-code-tool-allowlist) | [GitHub Security Advisory](https://github.com/anthropics/claude-code/security/advisories)

### Active Exploitation — Trojanized "Claude Code Plugins" Continue Spreading
**Status:** Active campaign; takedowns ongoing

Trend Micro and Socket published joint telemetry covering the past week. Despite Anthropic's takedown of 14 trojanized GitHub repositories impersonating Claude Code plugins, attackers re-uploaded under typo-squatted org names within hours. New variants now ship a multi-stage loader: stage 1 is a benign-looking VS Code extension manifest; stage 2 fetches a wasm-packed infostealer over `cloudflarepages.dev` subdomains, evading typical npm/pypi scanners.

- 11 confirmed payload variants observed in the past 7 days.
- Targets: `.env`, `~/.aws/credentials`, `~/.ssh/`, browser session stores, and notably **MCP server config files** (`~/.config/claude/mcp.json`).
- Defenders should monitor outbound DNS for `*.cloudflarepages.dev` from developer machines and audit MCP config files for unfamiliar STDIO server entries.

Sources: [Trend Micro](https://www.trendmicro.com/en_us/research/26/e/claude-code-plugin-trojans-may-2026-update.html) | [Socket](https://socket.dev/blog/claude-code-impostor-plugins-multi-stage-loader)

## Supply Chain

### Slopsquatting — Snyk Releases First Open Dataset of Hallucinated Packages
**Status:** Confirmed exploitation; mitigation tooling improving

Snyk published `slop-corpus-v1`, an open dataset of 84,312 hallucinated package names observed across instrumentation runs of GPT-4o, Claude 3.7/4.x, Gemini 2.5/3.0, DeepSeek-V3, and Llama-3.1 over a six-month window. Of those names, **2,184 (2.6%)** were already registered on npm or PyPI at the time of dataset publication; **at least 71** carry post-install scripts consistent with credential-theft intent. The corpus is intended to feed lockfile linters and pre-install warning systems.

- Reproducibility figure refined: **47%** of hallucinations repeat across 10 independent queries (up from earlier 43% estimate, narrower CI).
- Snyk's `npx slopcheck` CLI flags any dependency present in the corpus and is now bundled into Snyk Code's CI plugin.
- Aikido reports two additional self-propagating packages this week — `lodash-defer` and `react-async-pipe` — both observed being installed by Cursor and Claude Code agents in instrumented honeypot CI runs.

Sources: [Snyk Research](https://snyk.io/articles/slop-corpus-v1-release/) | [Aikido Honeypot Report](https://www.aikido.dev/blog/slopsquatting-honeypot-may-2026) | [Bleeping Computer](https://www.bleepingcomputer.com/news/security/ai-hallucinated-code-dependencies-become-new-supply-chain-risk/)

### MCP Architectural RCE — Anthropic Publishes "Hardening Guide" in Lieu of Protocol Patch
**Status:** Architectural flaw still upstream-unpatched; vendor-published mitigations

Anthropic published a hardening guide for MCP server implementers covering the STDIO command-execution issue first reported by OX Security in April. The guide reaffirms that Anthropic considers the current behavior "expected by design" and provides three implementation-level mitigations:

1. Wrap STDIO server invocations in a sandbox (suggested: bubblewrap, Firejail, container).
2. Validate all server-command argv tokens before invocation.
3. Treat the success of `os.execve` prior to handshake as adversarial.

The guide does **not** modify the protocol or SDK defaults. Downstream impact: 7,000+ publicly accessible servers and 200,000 instances remain in the original vulnerable configuration unless re-deployed with new wrappers. CSA called the guidance "responsibility-shifted, not resolved."

## Research & Advisories

### Trail of Bits — Argument Injection Mitigation Proposal
**Status:** Research advisory; reference implementation released

Trail of Bits' long-standing argument-injection-via-allowlisted-commands finding now has a reference mitigation. The team published `argv-fence`, an open-source Go library that wraps allowlisted commands and rejects argv tokens matching common injection patterns (`-exec`, `--exec`, shell metacharacter pass-through, `--`-suffixed flag re-introduction). Cursor, Aider, and OpenHands maintainers have indicated interest in integrating; no agent has merged the dependency yet.

Source: [Trail of Bits — argv-fence](https://blog.trailofbits.com/2026/05/argv-fence-mitigating-argument-injection/) | [Original 2025 Post](https://blog.trailofbits.com/2025/10/22/prompt-injection-to-rce-in-ai-agents/)

### Cisco Talos — "Agent-on-Agent" Attack Pattern Documented
**Status:** Research advisory

Cisco Talos described a class they call **agent-on-agent prompt injection**: where one AI coding agent's output (PR description, commit message, tool-call result) is later consumed by a second agent on a different developer's machine. Demonstrated with a Cursor commit message hijacking a Claude Code review session days later. The pattern doesn't require attacker code execution at any point — only the ability to have content reach a downstream agent's context window.

Source: [Talos Research](https://blog.talosintelligence.com/agent-on-agent-prompt-injection-2026/)

### Veracode — "State of AI-Assisted Software Security 2026 H1" Report
**Status:** Research advisory

Key findings from the half-yearly report (released 2026-05-05):
- **48%** of AI-generated code commits contain at least one OWASP Top 10 vulnerability (up from 45% in Q4 2025).
- AI-assisted developers ship 3.6× more commits per week but introduce security findings at **11×** the rate of unassisted peers.
- Median time-to-remediate for AI-introduced findings: 23 days (vs. 19 days for human-introduced findings) — attributed to higher false-confidence and lower review attention.
- **62%** of teams using AI agents have no policy distinguishing agent-authored from human-authored commits in code review SLAs.

Source: [Veracode H1 2026 Report](https://www.veracode.com/state-of-software-security-ai-2026-h1)
