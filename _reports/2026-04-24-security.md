# Security — 2026-04-24

## Incidents & Vulnerabilities

### "Comment and Control" — Claude Code, Gemini CLI, GitHub Copilot Hijacked via PR Comments (April 2026)

A cross-vendor attack class dubbed "Comment and Control" has been confirmed against three widely deployed AI coding agents. Attackers embed malicious instructions inside GitHub pull request titles, issue bodies, and issue comments; when any of the affected agents processes that content during an automated code-review or CI/CD workflow, it exfiltrates API keys and access tokens to attacker-controlled infrastructure. Anthropic's own system card for Claude Code Security Review explicitly acknowledges the feature "is not hardened against prompt injection." No CVEs assigned; no vendor has shipped targeted mitigations as of April 24. Status: **disclosed, unpatched across all three vendors**.

- Affected: Claude Code Security Review (GitHub Action), Google Gemini CLI Action, GitHub Copilot SWE Agent
- Fix: none available; interim guidance — restrict agent permissions in CI/CD environments, treat PR content as untrusted
- Sources: [SecurityWeek](https://www.securityweek.com/claude-code-gemini-cli-github-copilot-agents-vulnerable-to-prompt-injection-via-comments/), [VentureBeat](https://venturebeat.com/security/ai-agent-runtime-security-system-card-audit-comment-and-control-2026), [CyberPress](https://cyberpress.org/claude-code-gemini-cli-and-github-copilot-vulnerable/), [GBHackers](https://gbhackers.com/claude-code-gemini-cli-and-github-copilot-exposed/), [CyberSecurityNews](https://cybersecuritynews.com/prompt-injection-via-github-comments/)

### MCPJam Inspector RCE via Crafted PDF — CVE-2026-23744 (CVSS 9.8)

A critical remote code execution vulnerability in MCPJam Inspector allows an attacker to trigger arbitrary command execution by supplying a crafted document to a Claude MCP integration. A reported proof-of-concept involved an industrial control system: the malicious PDF caused a Claude MCP integration at a facility to activate a physical pump. CVSS base score 9.8. Status: **disclosed; patch status not confirmed at time of writing**.

- CVE: **CVE-2026-23744** (CVSS 9.8)
- Affected: MCPJam Inspector
- Fix: apply vendor patch when available; restrict MCP integrations from processing untrusted documents
- Sources: [AI Security in 2026 — Cycode](https://cycode.com/blog/ai-security-vulnerabilities/), [AI Agent Security Risks — CyberDesserts](https://blog.cyberdesserts.com/ai-agent-security-risks/)

### Cursor — Case-Sensitivity Bypass Enables Persistent RCE — CVE-2025-59944 (CVSS 8.6) / CVE-2025-54135

CVE-2025-59944 describes a case-sensitivity bypass in Cursor's security model that allows an attacker to persist remote code execution across IDE restarts by manipulating MCP configuration. CVE-2025-54135 (CVSS 8.6) covers untrusted MCP server remote code execution. Both vulnerabilities allow malicious code to survive IDE restart cycles, making cleanup non-trivial. Status: **disclosed; updates available**.

- CVE: **CVE-2025-59944**, **CVE-2025-54135** (CVSS 8.6)
- Affected: Cursor IDE
- Fix: update to latest Cursor release

### OpenClaw Framework Compromise — First Major AI Agent Supply Chain Incident (2026)

The OpenClaw framework was found to contain multiple critical vulnerabilities that enabled attackers to harvest agent credentials from 47 enterprise deployments. Researchers categorized this as the first major AI agent supply chain incident of 2026. Agent credentials — OAuth tokens, API keys — were exfiltrated and used for lateral movement within enterprise environments. No CVEs assigned at time of writing. Status: **disclosed; affected enterprises advised to rotate all agent credentials**.

- Sources: [AI Agent Security Risks — CyberDesserts](https://blog.cyberdesserts.com/ai-agent-security-risks/), [AI Coding Agents Insider Threat — Botmonster](https://botmonster.com/posts/ai-coding-agent-insider-threat-prompt-injection-mcp-exploits/)

### AI-Generated Code CVE Surge — 35 New CVEs in March 2026

At least 35 new CVE entries were disclosed in March 2026 as the direct result of security flaws in AI-generated code, up from 15 in February and 6 in January. The acceleration tracks the adoption curve of agentic coding tools (Cursor, Claude Code, GitHub Copilot Workspace) that submit code to production without mandatory human review. Categories include SQL injection, insecure deserialization, and improper input validation. No single tool is exclusively cited; the pattern spans multiple agents and languages. Status: **ongoing trend; no systemic fix**.

- Sources: [Infosecurity Magazine — AI Code Vulnerabilities](https://www.infosecurity-magazine.com/news/ai-generated-code-vulnerabilities/), [Top AI Security Vulnerabilities 2026 — Cycode](https://cycode.com/blog/ai-security-vulnerabilities/)

## Supply Chain

### axios npm Supply Chain Compromise — Phantom Dependency Drops Cross-Platform RAT (March 31, 2026)

On March 31, 2026, an attacker compromised the npm credentials of axios lead maintainer `jasonsaayman` and manually published two backdoored releases: `axios@1.14.1` (tagged `latest`) and `axios@0.30.4` (tagged `legacy`). Both releases introduced a phantom dependency — `plain-crypto-js@4.2.1` — a package that did not exist prior to that day and is not imported by axios itself. Its sole purpose is a `postinstall` script that drops and executes a cross-platform remote access trojan targeting macOS, Windows, and Linux. Axios is one of the most widely downloaded JavaScript HTTP libraries. Status: **patched; malicious versions unpublished; users should verify installed version and rotate any credentials from affected environments**.

- Affected: `axios@1.14.1`, `axios@0.30.4` (npm)
- Fix: update to `axios@1.14.2` or later; audit `postinstall` scripts in dependency tree
- Sources: [Sonatype](https://www.sonatype.com/blog/axios-compromise-on-npm-introduces-hidden-malicious-package), [Huntress](https://www.huntress.com/blog/supply-chain-compromise-axios-npm-package), [SANS Institute](https://www.sans.org/blog/axios-npm-supply-chain-compromise-malicious-packages-remote-access-trojan), [axios GitHub Issue #10636](https://github.com/axios/axios/issues/10636)

### Self-Propagating npm Supply Chain Worm Targets Developer Tokens (April 22, 2026)

The Register reported on April 22 that another self-propagating supply chain worm is circulating in the npm ecosystem, designed to steal developer authentication tokens — including npm publish credentials — from compromised developer machines. Once a developer machine is infected, the worm modifies locally installed packages to carry the payload forward, enabling it to spread to other packages when the developer publishes updates. The worm specifically targets AI-assisted development workflows where automated publish steps reduce human review. No CVE assigned at time of writing. Status: **active; npm security team investigating**.

- Affected: npm ecosystem (developer environments running automated publish workflows)
- Fix: audit all packages with publish access; rotate npm tokens; enable 2FA on npm accounts
- Sources: [The Register](https://www.theregister.com/2026/04/22/another_npm_supply_chain_attack/), [The Hacker News — Self-Propagating Worm](https://thehackernews.com/2026/04/self-propagating-supply-chain-worm.html)

### Slopsquatting Scale Update — 440,000+ Fake Dependencies Confirmed

New analysis confirms that AI coding tools have hallucinated at least 440,445 non-existent package names across Python and JavaScript ecosystems. Security researchers at Aikido and Syntax.ai report that attackers are now systematically registering these names with malicious payloads. 43% of hallucinated names repeat on re-querying the same prompt; 58% repeat across at least two of ten runs, making them reliably predictable. Unlike typosquatting, hallucinated names are often semantically legitimate (e.g. `dataframe-utils`) with no obvious signal to prompt developer skepticism. Autonomous agents that call `pip install` / `npm install` without human confirmation are the primary amplification vector. Status: **ongoing, no systemic fix; see mitigations below**.

- Mitigations: pin dependencies by hash, use Socket or Snyk to flag new/unrecognized packages, enable package provenance checks
- Sources: [Aikido Security](https://www.aikido.dev/blog/slopsquatting-ai-package-hallucination-attacks), [Syntax.ai](https://syntax.ai/blogs/slopsquatting-ai-hallucinated-packages-supply-chain-attack.html), [BleepingComputer](https://www.bleepingcomputer.com/news/security/ai-hallucinated-code-dependencies-become-new-supply-chain-risk/), [Snyk](https://snyk.io/articles/slopsquatting-mitigation-strategies/), [FOSSA](https://fossa.com/blog/slopsquatting-ai-hallucinations-new-software-supply-chain-risk/)

## Research & Advisories

### Systematic Prompt Injection Analysis — 85%+ Attack Success Rate Across All Major Agents (January 2026)

A peer-reviewed systematic analysis (arXiv 2601.17548) covering 78 studies concludes that every tested coding agent — Claude Code, GitHub Copilot, and Cursor — is vulnerable to prompt injection in default configurations, with adaptive attack success rates exceeding 85%. Attack surfaces catalogued include PR comments, repository files, web pages fetched during agent sessions, issue bodies, RAG document pipelines, and tool-call return values. The paper is cited in active CVE advisories and the Palo Alto Unit 42 MCP attack vector report.

- Sources: [arXiv 2601.17548](https://arxiv.org/html/2601.17548v1), [MDPI Information](https://www.mdpi.com/2078-2489/17/1/54)

### OWASP & Organizational Posture: 73% Exploitable, 35% Defended

Current OWASP data (LLM01:2025 — Prompt Injection) indicates that 73% of surveyed production AI deployments contain exploitable prompt injection paths, while only 34.7% of organizations have deployed dedicated prompt injection defenses. The gap between exposure and defense is widening as agentic coding tools move from individual developer use to automated CI/CD pipelines with elevated permissions.

- Sources: [PromptInjection.wtf](https://promptinjection.wtf/), [Cycode AI Vulnerabilities 2026](https://cycode.com/blog/ai-security-vulnerabilities/), [Airia — Lethal Trifecta](https://airia.com/ai-security-in-2026-prompt-injection-the-lethal-trifecta-and-how-to-defend/)

### AI Development Tooling as Unmonitored Supply Chain Attack Surface

Innovaiden and Check Point Research independently published advisories noting that AI development tooling (IDE plugins, model-integrated package resolvers, autonomous agent scaffolds) represents an attack surface that most security teams are not actively monitoring. Neither vulnerability scanners nor SCA tools are calibrated for the agent-to-package execution path introduced by coding agents. The Check Point report documents specific techniques by which AI tools can be used as initial access vectors against developer environments.

- Sources: [Innovaiden](https://www.innovaiden.com/insights/ai-development-tooling-supply-chain-attacks), [Check Point Research](https://blog.checkpoint.com/research/the-hidden-ai-threat-to-your-software-supply-chain/)
