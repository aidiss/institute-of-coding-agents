# Security Brief — 2026-05-03

Track of vulnerabilities, supply chain attacks, and safety incidents affecting AI coding agents.

---

## Incidents & Vulnerabilities

### CVE-2026-26268 — Cursor IDE Arbitrary Code Execution via Git Hook Interaction
**Status: Disclosed / Patch status unconfirmed**

Novee Security published a high-severity arbitrary code execution vulnerability in Cursor, the popular AI-powered IDE. The root cause is a feature interaction between Git's hook execution model and Cursor's AI agent, which becomes exploitable the moment the agent autonomously performs Git operations inside a repository it does not control. A malicious repository can embed a crafted `.git/hooks/` payload that executes OS commands when the agent triggers a hook-activating operation (e.g., `git commit`, `git checkout`). No prior trust relationship or user confirmation is needed if the agent has been granted autonomous mode.

- **Affected:** Cursor IDE (all versions with autonomous Git operations enabled)
- **CVE:** CVE-2026-26268
- **Severity:** High
- **Attack vector:** Malicious repository → agent-triggered Git operation → hook execution → arbitrary OS commands
- **Fix:** Patch status unconfirmed at time of writing; disable autonomous Git operations until vendor advisory is released

### CVE-2026-21520 — Microsoft Copilot Studio Indirect Prompt Injection (CVSS 7.5)
**Status: Patched January 2026 / Data exfiltration observed post-patch**

Microsoft patched an indirect prompt injection vulnerability in Copilot Studio on 15 January 2026 (CVE-2026-21520, CVSS 7.5). However, Capsule Security's subsequent testing confirmed that data continued to exfiltrate after the official patch, with attacker-controlled content in documents processed by Copilot Studio still capable of redirecting agent output to external endpoints. The patch addressed one injection surface but did not eliminate the broader class of indirect injection attacks against the platform.

- **Affected:** Microsoft Copilot Studio
- **CVE:** CVE-2026-21520
- **CVSS:** 7.5 Medium
- **Fix:** Patched January 15, 2026; however full exfiltration class remains unresolved

### CVE-2026-21852 — AI Coding Tool API Traffic Redirect via Malicious Repository
**Status: Disclosed / Check Point Research**

Check Point Research documented CVE-2026-21852, in which cloning a specially crafted repository silently redirects an AI coding tool's API traffic to an attacker-controlled server. The technique abuses agent startup configuration hooks to insert a proxy between the IDE extension and its backend, allowing interception of credentials and completions before the developer sees any trust prompt. The attack was validated against multiple unnamed IDE extensions. Cloud credentials for AWS, Azure, and GCP were among the documented exfiltrated artifacts.

- **Affected:** Multiple unnamed AI coding tool extensions (cloning an attacker repository sufficient for exploitation)
- **CVE:** CVE-2026-21852
- **Fix:** Vendor-specific; no single patch; mitigations include restricting extension permissions and auditing startup hook execution

### Triple-Agent Prompt Injection — Claude Code, Gemini CLI, and Copilot Simultaneously Exfiltrate Secrets
**Status: Disclosed / No CVEs filed by vendors**

VentureBeat and Security Boulevard reported that a single prompt injection payload successfully leaked secrets from Claude Code, Gemini CLI, and GitHub Copilot simultaneously. Researchers demonstrated the payload in a crafted repository README, where all three agents — when executing a code review task — read the instruction and transmitted discovered API keys and environment variable contents to an attacker-controlled endpoint. Notably, none of the three vendors filed a CVE or shipped a GitHub Security Advisory at disclosure time, despite public proof-of-concept availability.

- **Affected:** Claude Code, Gemini CLI, GitHub Copilot (all current versions at time of disclosure)
- **Attack vector:** Malicious content in repository README → agent reads and executes exfiltration instruction
- **Fix:** No vendor patches issued; runtime sandboxing and network egress controls are the primary mitigations

### Self-Propagating Prompt Injection Chain — 506 Agent Hops Traced Before Patch
**Status: Patched / Post-incident analysis**

404 Media traced a prompt injection that spread through a multi-agent network for 506 distinct hops before being detected and patched — described as the closest observed approximation to a self-propagating worm in agentic AI. The injection was embedded in a document processed by one agent, whose output was consumed by downstream agents that then forwarded the payload in their own outputs. The incident demonstrates that multi-agent architectures amplify single-point injection vulnerabilities into ecosystem-scale events.

- **Affected:** Unnamed multi-agent orchestration platform
- **Fix:** Patched by vendor; architectural recommendation to treat all inter-agent messages as untrusted input

### GitHub Actions Credential Theft via Malicious Pull Requests
**Status: Disclosed / Ongoing**

Attackers opened over 500 malicious pull requests targeting GitHub Actions workflows, exploiting the `pull_request_target` trigger to steal AWS, Azure, and GCP credentials from workflow environments. Several of the malicious PRs were found to have been partially drafted by AI coding agents on compromised developer machines, blurring the line between supply chain attack and AI-assisted credential theft.

- **Affected:** GitHub repositories using `pull_request_target` with exposed cloud credentials in workflow environments
- **Fix:** Restrict `pull_request_target` permissions; pin secrets to environments with protection rules

## Supply Chain

### MCP Servers Exposed Without Authentication — 492 Confirmed by Trend Micro
**Status: Ongoing / No central remediation**

Trend Micro's April 2026 sweep found 492 MCP servers exposed to the open internet with no authentication layer. These servers — used by Claude Code, Cursor, and other MCP-enabled agents to access tools, file systems, and internal APIs — accept requests from any client. An attacker who locates an exposed server can invoke arbitrary registered tools, including file read/write, shell execution, and database queries, depending on the server's registered capabilities.

- **Scale:** 492 publicly accessible, unauthenticated MCP servers confirmed
- **Fix:** Place MCP servers behind authenticated reverse proxies; block direct internet exposure; log all tool invocations

### Secrets Sprawl in MCP Configuration Files — 24,000+ Credentials on Public GitHub
**Status: Ongoing**

GitGuardian's 2026 scanning found more than 24,000 unique secrets embedded in MCP configuration files (`claude_desktop_config.json`, `.cursor/settings.json`, and equivalents) committed to public GitHub repositories. Over 2,100 of these credentials were confirmed still valid at discovery time. Remote MCP servers routinely require hardcoded API keys, OAuth tokens, and service credentials in these files; AI coding tools that generate or modify MCP configurations can inadvertently commit these secrets when staging configuration changes.

- **Credentials at risk:** OpenAI keys, Anthropic keys, OAuth tokens, service credentials
- **Fix:** Add MCP config files to `.gitignore`; use secret-scanning pre-commit hooks; rotate any confirmed-valid exposed credentials

### Slopsquatting — Coding Agents Installing Hallucinated Dependencies Autonomously
**Status: Ongoing / No ecosystem-level fix**

Security Boulevard's March 2026 analysis highlighted the compounding risk from coding agents such as Cursor, Claude Code, and Copilot Workspace acting as autonomous participants in the software development lifecycle — selecting and installing dependencies without human review. Commercial models hallucinate non-existent package names in ~5.2% of cases; open-source models at ~21.7%. Because 58% of hallucinated package names are repeated consistently across runs, attackers have automated monitoring of LLM outputs to pre-register those names on PyPI and npm. A security researcher's test registration of the hallucinated Python package `huggingface-cli` accumulated over 30,000 downloads within three months.

- **Ecosystem status:** No detection deployed in PyPI or npm for hallucination-targeted package names
- **Fix:** Lock dependency manifests before agent execution; run `pip-audit` / `npm audit` on all AI-generated dependency additions; use private registries where possible

### Vibe Coding CVE Surge — 35 CVEs in One Month from AI-Generated Code
**Status: Ongoing / Research warning**

Georgia Tech's Vibe Security Radar project tracked 35 CVEs in a single month (March 2026) directly attributable to code written by AI coding tools, with researchers estimating the true ecosystem count is five to ten times higher. Veracode's parallel benchmark found that 45% of AI-generated code samples introduce OWASP Top 10 vulnerabilities — primarily SQL injection, path traversal, and insecure deserialization — when developers do not apply security-aware prompting or review. The Cloud Security Alliance characterized this as "vibe coding's security debt" accruing at unsustainable rates.

## Research & Advisories

### OWASP GenAI Exploit Round-up Report — Q1 2026
OWASP's GenAI Security Project published its Q1 2026 exploit round-up on April 14, 2026, documenting the transition from theoretical AI security risks to active exploitation across enterprise deployments. The report classifies prompt injection as the dominant vulnerability class (present in 73% of assessed production AI deployments, up from 60% in 2025), and elevates supply chain attacks via MCP and hallucinated dependencies to Tier 1 threats. The report notes that no frontier model from OpenAI, Google, or Anthropic remained reliably resistant to prompt injection after applying vendor-recommended defenses.

Reference: [genai.owasp.org — Q1 2026 Exploit Round-up](https://genai.owasp.org/2026/04/14/owasp-genai-exploit-round-up-report-q1-2026/)

### Unit 42 — New Prompt Injection Attack Vectors via MCP Sampling
Palo Alto Networks Unit 42 published research documenting attack vectors introduced by MCP's sampling feature, which allows MCP servers to request model completions from the connected AI agent. Without adequate access controls, malicious MCP servers can use sampling callbacks to extract conversation context, inject additional instructions, or pivot to data sources accessible to the agent. The paper identifies the sampling feature as a second-order injection surface distinct from the previously reported STDIO design flaw.

Reference: [unit42.paloaltonetworks.com — MCP Attack Vectors](https://unit42.paloaltonetworks.com/model-context-protocol-attack-vectors/)

### Unit 42 — Web-Based Indirect Prompt Injection Observed In the Wild
A separate Unit 42 report documented the first confirmed in-the-wild use of indirect web-based prompt injection against AI agents that browse external URLs during task execution. Malicious instructions embedded in attacker-controlled web pages are retrieved and executed by agents performing research or link-preview tasks, allowing zero-click data exfiltration from the agent's accessible context — including open files, environment variables, and clipboard contents.

Reference: [unit42.paloaltonetworks.com — AI Agent Prompt Injection in the Wild](https://unit42.paloaltonetworks.com/ai-agent-prompt-injection/)

### A Timeline of MCP Security Breaches — AuthZed
AuthZed published a timeline cataloguing all publicly disclosed MCP-related security incidents from November 2024 through April 2026. The timeline covers 18 distinct incidents, including tool poisoning attacks, rug-pull MCP server swaps, authentication bypass exploits, and the STDIO RCE cascade. It serves as a reference for organizations assessing MCP exposure. The Vulnerable MCP Project database (vulnerablemcp.info) is maintained in parallel as a machine-readable CVE index.

Reference: [authzed.com — Timeline of MCP Breaches](https://authzed.com/blog/timeline-mcp-breaches)
