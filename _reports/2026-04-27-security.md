## Headlines

- **RoguePilot** (Orca Security) demonstrates a complete, weaponized exploit chain for GitHub Copilot that achieves code execution via PR-embedded malicious instructions — no social engineering beyond a developer opening a pull request.
- **Systematic CVE suppression**: Anthropic, Google, and Microsoft paid bug bounties for AI agent vulnerabilities and patched quietly, issuing no CVEs and no public security advisories. Researchers who received payment are now speaking out.
- **Cloud Security Alliance** published a formal research note on Google Antigravity's sandbox escape (April 22, 2026), detailing how the `find_by_name` native tool fires before Secure Mode restrictions are evaluated.

- **OWASP AI Agent Top 10** is circulating as a pre-release draft; memory poisoning is formally classified as a distinct threat class.

## Incidents & Vulnerabilities
_As of 2026-04-27_

### RoguePilot — Weaponized GitHub Copilot Exploit Chain (Orca Security)

**Disclosed:** April 2026 | **Researcher:** Orca Security | **Type:** Prompt injection → arbitrary code execution | **Status:** Disclosed; patch status not confirmed at time of writing

Orca Security published "RoguePilot," a proof-of-concept exploit that chains multiple previously reported GitHub Copilot weaknesses into a single reliable attack. The attack flow:

1. Attacker submits a pull request to a target repository containing hidden prompt injection instructions in the PR description
2. A developer opens the PR and asks Copilot to summarize or review it — or Copilot processes it automatically via an agent workflow
3. Injected instructions override Copilot's operating context, directing it to generate code containing a shell payload
4. The payload executes in the developer's local environment (or CI runner) when Copilot's suggestion is applied or auto-run

RoguePilot is notable because it requires no custom tooling: the attack runs entirely through Copilot's standard code review interface and requires no special permissions beyond write access to a public repository (sufficient to open a PR). Orca confirmed the exploit against Copilot's JetBrains and VS Code integrations.

*Source: [Orca Security — RoguePilot: Critical GitHub Copilot Vulnerability Exploit](https://orca.security/resources/blog/roguepilot-github-copilot-vulnerability/)*

### CVE Suppression — Anthropic, Google, Microsoft Patched Quietly, Issued No Public Advisories

**Disclosed:** April 2026 | **Reporters:** Multiple researchers cited by The Next Web | **Type:** Disclosure process failure | **Status:** Ongoing controversy

The Next Web reports that Anthropic, Google, and Microsoft each paid bug bounties for AI agent vulnerabilities discovered through their respective bounty programs and subsequently patched the issues — but issued no CVEs, no GitHub Security Advisories, and no public notifications to affected users.

- Researchers who reported the prompt injection flaws in Claude Code (Security Review feature), Google's Gemini CLI (`run-gemini-cli`), and GitHub Copilot received payments ranging from $500 to $1,337
- None of the three vendors filed CVE requests or published advisories before researchers independently disclosed
- All three products remain in production; no version-specific affected/fixed information has been released by vendors

This pattern is structurally significant: the three-agent simultaneous compromise (covered April 26) was only publicly disclosed because the researchers chose to speak out. Had they accepted payment without disclosure, the attack class would remain unknown to defenders.

*Source: [The Next Web — Anthropic, Google, and Microsoft paid AI agent bug bounties, then kept quiet about the flaws](https://thenextweb.com/news/ai-agents-hijacked-prompt-injection-bug-bounties-no-cve)*

### Microsoft Copilot — "Reprompt" Attack (Patched Jan 13–14, 2026)

**CVE:** Under investigation | **Type:** Prompt injection → staged command execution → data exfiltration | **Status:** Patched

For completeness: the Reprompt attack against Microsoft Copilot Personal (discovered by Varonis Threat Labs, patched January 13–14, 2026) used a URL parameter to auto-execute prompts, bypassed safety guardrails via a double-request technique, and exfiltrated sensitive data to an attacker-controlled server by fetching staged commands server-side — making the initial URL appear benign upon inspection. Data stolen included usernames, calendar events, recent files, conversation history, and location data.

Distinct from CVE-2026-21516 (JetBrains plugin RCE); the Reprompt attack targeted Microsoft Copilot Personal via the web interface.

*Sources: [Malwarebytes — Reprompt attack lets attackers steal data from Microsoft Copilot](https://www.malwarebytes.com/blog/news/2026/01/reprompt-attack-lets-attackers-steal-data-from-microsoft-copilot) | [SC Media — Reprompt attack exploits Microsoft Copilot for data theft](https://www.scworld.com/brief/reprompt-attack-exploits-microsoft-copilot-for-data-theft) | [eSecurity Planet — Microsoft Copilot Reprompt Attack Enables Stealthy Data Exfiltration](https://www.esecurityplanet.com/artificial-intelligence/microsoft-copilot-reprompt-attack-enables-stealthy-data-exfiltration/)*

### MCP Flaw — Banking Sector Exposure Highlighted

**Status:** Protocol-level flaw unpatched; Anthropic declined to modify architecture | **New development:** Sector-specific risk warning published

American Banker reports that financial institutions deploying AI coding tools with MCP integrations face unremediated risk from the STDIO RCE design flaw (see April 26 report). The banking-sector angle is notable for two reasons:

1. **Regulatory exposure**: Financial institutions operating under SOC 2, PCI-DSS, or federal banking regulations face audit findings if they cannot demonstrate a remediation path for a known critical vulnerability — and Anthropic's position that the behavior is "expected" eliminates the vendor patch as a resolution option
2. **Privilege escalation risk**: Developer workstations in financial institutions often have elevated access to production systems, secrets vaults, and financial APIs; MCP RCE in this environment can reach far beyond the developer's local machine

*Source: [American Banker — Unpatched AI flaw poses risk to banking sector](https://www.americanbanker.com/news/unpatched-ai-flaw-poses-risk-to-banking-sector)*

## Research & Advisories
_As of 2026-04-27_

### CSA AI Safety Initiative — Antigravity Sandbox Escape Research Note (April 22, 2026)

**Published:** April 22, 2026 | **Researcher:** Pillar Security (via Cloud Security Alliance)

The Cloud Security Alliance AI Safety Initiative published a formal research note documenting the full sandbox escape chain in Google's Antigravity agentic IDE. Key technical findings:

- The `find_by_name` native tool is invoked before Secure Mode security restrictions are evaluated, creating a pre-filter execution window
- An attacker can craft a prompt injection that triggers `find_by_name` with a malicious path argument during this window, achieving directory traversal outside the sandboxed environment
- The escape enables read access to the host filesystem and, depending on tool configuration, shell command execution
- The attack does not require special permissions or user interaction beyond having the IDE open with an active agent session

Google issued a patch after Pillar Security's responsible disclosure. The CSA note recommends that agentic IDEs implement tool-call authorization checks before any tool fires, regardless of operating mode.

*Source: [Cloud Security Alliance — Antigravity Sandbox Escape: Prompt Injection and Native Tool Abuse](https://labs.cloudsecurityalliance.org/research/csa-research-note-agentic-ide-prompt-injection-sandbox-escap/)*

### OWASP AI Agent Top 10 — Memory Poisoning Formalized as Threat Class

**Status:** Pre-release draft circulating | **Source:** SwarmSignal AI Agent Security 2026

The OWASP AI Agent Top 10 threat taxonomy is in late-draft stage. Confirmed inclusions relevant to AI coding agents:

| Rank | Threat | Relevance to coding agents |
|------|--------|---------------------------|
| 1 | Prompt injection | Core attack vector; affects all agents that process external content |
| 2 | Memory poisoning | Agent long-term memory (vector stores, conversation history) can be persistently corrupted by injected content |
| 3 | Tool/plugin abuse | MCP and other tool interfaces used to escalate from text injection to code execution |
| 4 | Insecure agent-to-agent communication | Multi-agent pipelines propagate poisoned context across agents |
| 5 | Excessive agent permissions | Ambient authority problem; agents inherit developer-level access without scoping |

Memory poisoning as a distinct OWASP category is new: prior frameworks treated it as a variant of prompt injection. Separating it acknowledges that persistent agent memory creates a durable attack surface — a successful poisoning attack on an agent's vector store affects all future sessions, not just the current one.

*Source: [SwarmSignal — AI Agent Security in 2026: Prompt Injection, Memory Poisoning, and the OWASP Top 10](https://swarmsignal.net/ai-agent-security-2026/)*

### ResearchGate — "Prompt Injection in 2026: Why Digital Assistants Need System Boundaries, Not Just Better Prompts"

A new paper circulating on ResearchGate argues that the current industry approach to prompt injection defense — better system prompts, filtering, and model fine-tuning — is architecturally insufficient. The paper's thesis: prompt injection is a boundary problem, not a content problem. Models trained on instruction-following data cannot reliably distinguish "this is data to process" from "this is an instruction to follow" because the distinction is semantic, not structural. The proposed alternative is privilege separation at the tool call layer: agents should operate with a read-only context by default, and tool invocations that write, execute, or transmit data should require an out-of-band authorization signal that cannot be mimicked by text content.

This framing aligns with the CSA Antigravity research note's recommendation (above) and with the January 2026 arxiv paper on coding agent prompt injection (see April 26 report).

*Source: [ResearchGate — Prompt Injection in 2026: Why "Digital Assistants" Need System Boundaries, Not Just Better Prompts](https://www.researchgate.net/publication/399796681_Prompt_Injection_in_2026_Why_Digital_Assistants_Need_System_Boundaries_Not_Just_Better_Prompts)*

### Penligent AI — AI Agents Hacking in 2026: Defending the New Execution Boundary

Penligent AI's threat landscape summary frames the core problem as an "execution boundary" shift: in traditional software, the trust boundary is at the network perimeter or authentication layer. In agentic AI systems, the trust boundary is wherever the model's attention ends — which includes untrusted content (files, web pages, API responses, PR descriptions) that the agent processes in the same cognitive context as trusted instructions. Until models can enforce a structural distinction between trusted instructions and untrusted data, every piece of content that enters the agent's context window is a potential attack surface.

*Source: [Penligent AI — AI Agents Hacking in 2026: Defending the New Execution Boundary](https://www.penligent.ai/hackinglabs/ai-agents-hacking-in-2026-defending-the-new-execution-boundary/)*

## Analyst Note

Three developments from the April 26–27 window warrant specific attention:

**RoguePilot operationalizes the prompt injection kill chain.** The shift from theoretical PoC to a named, published, weaponized exploit (with PR-level reproducibility) means that GitHub Copilot users reviewing external pull requests are now operating in a confirmed hostile-input environment. Organizations using Copilot in any agentic or review mode should treat all external PR content as adversarial until GitHub issues a formal patch confirmation. "Await Copilot update" is not adequate risk management for production workflows.

**The CVE suppression pattern is a structural problem.** When vendors pay bounties without issuing CVEs or advisories, the information asymmetry works entirely in favor of attackers: researchers who find the same bug independently (or buy it from a broker) know the vulnerability exists and that the patch window is narrow and quiet. Defenders, SIEM vendors, and vulnerability scanners have no signal. The three vendors named (Anthropic, Google, Microsoft) all have the infrastructure to issue CVEs — the choice not to is a policy decision, not a capability limitation. Security teams should treat any AI coding tool as potentially carrying unannounced patches for undisclosed vulnerabilities.

**Memory poisoning as a distinct OWASP class is a maturity marker.** The field is past the point where "prompt injection" is a sufficient taxonomy. Persistent memory stores in agents (vector databases, conversation histories, fine-tuning datasets) represent a durable attack surface that survives agent restarts and user session boundaries. Teams using agents with long-term memory should assess whether those memory stores are isolated, auditable, and purgeable in the event of a suspected poisoning incident.

**Immediate actions (April 27 additions):**

- **GitHub Copilot:** If using Copilot in any agentic review mode, disable automatic processing of external PR content until RoguePilot is formally patched and a version number is confirmed by GitHub
- **Vendor patch tracking:** Do not rely solely on CVE feeds for AI coding tool vulnerability tracking; monitor vendor changelogs directly and subscribe to researcher disclosure channels (GitHub Security Lab, Orca Security, Pillar Security)
- **MCP in regulated industries:** Financial institutions and other regulated sectors should formally document the MCP STDIO RCE flaw as an open risk item with Anthropic's non-remediation position as the vendor response; this is required for accurate risk register maintenance
- **Agent memory hygiene:** Inventory all agent deployments with persistent memory (vector stores, conversation history files); establish a process for auditing and purging memory stores if a prompt injection incident is suspected
