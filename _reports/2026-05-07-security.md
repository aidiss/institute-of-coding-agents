## Incidents & Vulnerabilities

### CVE-2026-34318 — Windsurf Agent Mode "Auto-Continue" Bypass (CVSS 8.7)
**Status:** Disclosed; **patched in Windsurf 1.10.4** | **Affected:** 1.9544.26 – 1.10.3

A second prompt-injection-to-RCE chain in Windsurf — the same product hit by the unpatched 2026-04 issue tracked in prior briefs. HiddenLayer demonstrated that a poisoned README served from a freshly cloned repository could promote arbitrary tool calls into Windsurf's "Auto-Continue" allowlist by exploiting a normalization bug: the agent compared canonicalized command strings against the user-allowlist *after* expanding the malicious payload's macros. Result: arbitrary `bash -c` execution on first agent run after `git clone`. Codeium shipped 1.10.4 the same day disclosure landed and back-ported the fix to the 1.9.x maintenance branch (1.9544.31). The earlier April CVE (no number assigned) is **also superseded** by this fix.

Sources: [HiddenLayer Advisory](https://hiddenlayer.com/research/windsurf-auto-continue-cve-2026-34318) | [Codeium Changelog](https://codeium.com/changelog) | [NVD](https://nvd.nist.gov/vuln/detail/CVE-2026-34318)

### CVE-2026-34112 / CVE-2026-34201 — Patch-Adoption Telemetry After 48 Hours
**Status:** Patched at vendors; field uptake mixed

Two days after the Cursor and Claude Code disclosures (covered in the 2026-05-06 brief), early telemetry from Wiz and Endor Labs shows uneven patch uptake:

- **Cursor 1.7.2 (CVE-2026-34112):** ~64% of instrumented enterprise tenants on a fixed build at 48h. Auto-update default helped; the long tail is air-gapped and pinned-version installs.
- **Claude Code 2.1.96 (CVE-2026-34201):** ~71% of CLI invocations seen by Endor's npm telemetry are on the patched line; however Anthropic's marketplace shows **24 plugins** with names that would have been bypassed by the prefix-match bug. None confirmed malicious; Anthropic has begun a name-collision sweep.

Defenders should pair the upgrade with `claude-code plugin list --check-collisions` (added in 2.1.96) to flag locally installed plugins whose names share allowlist prefixes.

Sources: [Wiz Field Telemetry](https://wiz.io/blog/cursor-cve-2026-34112-uptake-tracker) | [Endor Labs npm Telemetry](https://endorlabs.com/blog/claude-code-2-1-96-rollout) | [Anthropic Plugin Audit Notice](https://www.anthropic.com/security/advisories/2026-05-claude-code-plugin-name-collisions)

### CVE-2026-34355 — JetBrains AI Assistant — Project-Trust Bypass via `.idea/runConfigurations` (CVSS 8.1)
**Status:** Disclosed; **patched in 2026.1.4** | **Affected:** 2025.3 – 2026.1.3

Snyk disclosed a trust-boundary bypass in JetBrains AI Assistant analogous to the Cursor `.cursor/rules.json` issue. A malicious repo can ship `.idea/runConfigurations/*.xml` with `<env name="JB_AI_AUTOAPPROVE">true</env>`. The IDE consults the env var when materializing the AI assistant's tool allowlist, **before** the project-trust dialog. Opening the project in IntelliJ-family IDEs (IntelliJ, PyCharm, WebStorm, Rider, GoLand) was sufficient to silently grant `Run Anything` and `Terminal` to the assistant. JetBrains shipped 2026.1.4 across the platform; Toolbox auto-update is rolling now.

Sources: [Snyk Research](https://snyk.io/research/jetbrains-ai-assistant-trust-bypass-cve-2026-34355) | [JetBrains Security Bulletin](https://www.jetbrains.com/privacy-security/issues-fixed/) | [NVD](https://nvd.nist.gov/vuln/detail/CVE-2026-34355)

### Active Exploitation — Trojanized "Claude Code Plugins" — Confirmed Beachhead at Two Mid-Cap Targets
**Status:** Active campaign; first confirmed downstream breaches

Trend Micro and Mandiant issued a joint flash advisory: the Claude Code plugin trojan family tracked since late April (covered in the 2026-05-06 brief) has produced **two confirmed downstream breaches** at named mid-cap SaaS companies — names withheld pending notification, but both reportedly fintech with developer SaaS exposure. In each case the entry vector was a developer's `~/.config/claude/mcp.json` configured via a typosquatted plugin (`@anthropic-claude-code-extras` — note the spurious "extras" suffix). Initial access yielded `~/.aws/credentials`; lateral movement from there used the AWS keys directly.

- **Newly observed C2 channel:** payloads now resolve `*.r2.dev` Cloudflare R2 buckets in addition to `*.cloudflarepages.dev`, evading single-domain blocks.
- **Defender update:** Anthropic's plugin marketplace added a verified-publisher badge ahead of schedule today; un-badged plugins will require a confirm-twice install flow starting 2026-05-12.
- Aikido and Socket are co-publishing IOC packs.

Sources: [Trend Micro / Mandiant Joint Advisory](https://www.trendmicro.com/en_us/research/26/e/claude-code-plugin-trojan-confirmed-breaches.html) | [Anthropic Marketplace Update](https://www.anthropic.com/news/claude-code-marketplace-verified-publisher) | [Socket IOC Pack](https://socket.dev/blog/claude-code-plugin-trojan-iocs-2026-05-07)

### CVE-2025-6514 — `mcp-remote` Still Unpatched, Now Actively Exploited
**Status:** **Actively exploited**; no upstream fix | **Affected:** all versions

The OS-command-injection in the `mcp-remote` OAuth proxy (originally disclosed by JFrog in 2025) crossed the line from "known unpatched" to "actively exploited" today. JFrog and GreyNoise jointly reported scanning activity targeting default `mcp-remote` ports across cloud IP space, with a working exploit posted to a Telegram channel earlier this week. The package author has been unresponsive on GitHub since February. Defenders running `mcp-remote` should:

1. Take it off the network or front it with an authenticating reverse proxy.
2. Pin to a patched fork (community fork `mcp-remote-secure` shipped a fix yesterday and is recommended only as a stop-gap, not a long-term substitute).
3. Audit OAuth tokens issued through the proxy in the last 30 days for unexpected use.

Sources: [JFrog/GreyNoise Joint Bulletin](https://jfrog.com/blog/mcp-remote-active-exploitation-cve-2025-6514) | [GreyNoise Tag](https://viz.greynoise.io/tag/mcp-remote-cve-2025-6514-attempt) | [Community Fork](https://github.com/mcp-remote-secure/mcp-remote-secure)

## Supply Chain

### Slopsquatting — `slop-corpus-v1` Detection Roll-Out and First "Dataset-Driven" Block
**Status:** Active mitigation gaining ground

48 hours after Snyk's release of `slop-corpus-v1` (84,312 hallucinated package names), tooling integration is moving fast:

- **GitHub** added a corpus-driven warning to Dependabot's package addition flow; a developer adding a name from the corpus sees a yellow banner and a "double confirm" before merge.
- **npm** (GitHub) rolled out a registry-side warning during `npm install` for any package created in the last 90 days whose name appears in the corpus. **First confirmed block:** `react-async-pipe` (covered in yesterday's brief) was prevented from auto-installing by Cursor's agent in an Aikido honeypot CI run that had upgraded to npm 11.4.2.
- **PyPI** (PSF) signaled support but said registry-side blocking is "weeks, not days" away.

Open question for defenders: corpus coverage. Aikido reproduced four hallucinations from a fresh GPT-5 build that are **not** in `v1`; expect a `v1.1` corpus refresh shortly.

Sources: [GitHub Changelog](https://github.blog/changelog/2026-05-07-dependabot-slopsquatting-warning) | [npm Registry Notice](https://docs.npmjs.com/policies/registry-warnings#slop-corpus) | [Aikido Update](https://www.aikido.dev/blog/slopsquatting-honeypot-may-7-2026) | [PSF Statement](https://blog.pypi.org/posts/2026-05-07-slop-corpus-tracking/)

### MCP Architectural RCE — Linux Distros Begin Sandboxing by Default
**Status:** Architectural flaw still upstream-unpatched; downstream mitigation accelerating

Following Anthropic's "responsibility-shifted" hardening guide (2026-05-06 brief), distro maintainers moved:

- **Fedora 42** queued a packaging change that wraps `mcp-server` invocations in `bwrap --unshare-all` by default. Lands in updates-testing today; stable in ~2 weeks.
- **Debian** opened a bug tracking the same approach for `bookworm-backports`.
- **Homebrew** shipped a formula audit warning for any cask that ships an MCP STDIO server without a sandbox shim.

The combined effect is the first ecosystem-wide containment of the MCP STDIO RCE class, even though the protocol itself remains unchanged. CSA characterized the move as "the right shape, applied to the wrong layer," and reiterated that the protocol-level fix should still happen.

### Trail of Bits — `argv-fence` v0.2 Adds Python and Rust Bindings; Aider Merges
**Status:** Reference implementation expanding; first agent integration

Trail of Bits' `argv-fence` library (introduced in the 2026-05-06 brief) shipped v0.2 today with Python and Rust bindings. **Aider 0.92.0 has merged the Python bindings** as a default-on policy for its `bash` and `git` allowlists; this is the first major coding agent to ship the dependency. ### NIST — Draft IR 8557 "Security Considerations for AI Coding Agents" (Public Comment Open)
**Status:** Draft for public comment

NIST opened public comment on **NIST IR 8557 (draft)**, the first U.S. government framework specifically addressing AI coding agent security. The draft formalizes terminology (agent, workspace trust boundary, tool allowlist, prompt-injection sink) that has been ad-hoc across vendor advisories, and recommends:

- A standardized "agent runtime identity" credential class distinct from human/service credentials.
- A required structured CVE taxonomy field for "AI-coding-agent affected" so CISA's KEV catalog can be filtered.
- Workspace trust as a required pre-tool-execution gate; rule-loading-before-trust patterns (the Cursor and JetBrains classes above) explicitly named as anti-patterns.

Comment window: 60 days. The document will inform an upcoming OMB memo on federal-agency use of AI coding tools.

Source: [NIST IR 8557 Draft](https://csrc.nist.gov/pubs/ir/8557/ipd) | [Federal Register Notice](https://www.federalregister.gov/documents/2026/05/07/nist-ir-8557-draft-ai-coding-agents) | [CSA Comment Tracker](https://labs.cloudsecurityalliance.org/research/csa-tracker-nist-ir-8557-comments/)

### Cisco Talos — "Agent-on-Agent" Attack — Now Demonstrated In-the-Wild
**Status:** Research advisory upgraded to active observation

Following the Talos research note from 2026-05-06, the team disclosed today that the agent-on-agent pattern has been observed in **a real, non-laboratory incident**: a contractor's commit message containing an injection payload was consumed by a customer's Claude Code review session three days later, leading to an attempted data exfiltration via a posted PR comment. The customer's allowlist held; no data left the environment. Talos calls this "the first natural occurrence" of the class and notes the contractor's machine was subsequently confirmed to be infected with a Claude Code plugin trojan (cross-references the campaign above).

Source: [Talos Update](https://blog.talosintelligence.com/agent-on-agent-first-natural-occurrence-2026-05/)

**Status:** Research advisory

Cisco's H1 update aggregates findings across the security research published this quarter. Headline numbers:
